# 검색 정책

> 방구석 철학자들 — 익명 커뮤니티의 게시글·댓글 검색 및 자동완성 정책.
> 최종 갱신: 2026-06-11

## 1. 개요

검색은 **게시글·댓글**을 대상으로 한다. 로그인·회원 개념이 없는 **익명 게시판**이며, 콘텐츠는 **매일 자정 전체 삭제**된다. 검색은 별도 색인 저장소 없이 PostgreSQL 본 테이블을 `pg_trgm`으로 실시간 조회한다. 색인 동기화 지연이 없으므로 자정 직후부터 새 콘텐츠가 즉시 검색에 반영된다.

검색 화면(`/search`)은 두 갈래로 동작한다.

| 갈래 | 동작 방식 | 매칭 방식 |
|---|---|---|
| **자동완성 드롭다운** | 입력 중 후보 제안(200ms 디바운스) | 접두(prefix) + 자모 점진 + 초성 |
| **통합 검색 결과** | 엔터·후보 선택·🔍 버튼으로 검색 실행 | 부분 문자열 + 초성 |

두 갈래는 매칭 방식이 의도적으로 다르다. 자동완성은 "입력 중인 단어를 완성"하는 목적이므로 접두 매칭이 적합하고, 통합 검색은 "이 단어가 들어 있는 글을 찾는" 목적이므로 부분 문자열 매칭이 적합하다.

> **자동완성 우선 채택 근거**: 드롭다운(쿼리 완성 제안)과 라이브 결과가 동시에 렌더링되면 같은 의도를 두 번 예측하는 데다, 드롭다운이 결과 카드·sticky 필터를 가리는 공간 충돌이 발생한다. 엔터·선택 시 검색하는 익숙한 흐름으로 충돌을 제거하고, 키스트로크당 요청 부하도 줄인다.

## 2. 검색 대상·가시성

| 타입 | 검색 필드 | 가시성 조건 |
|---|---|---|
| 게시글(POST) | `title`, `content`, `nickName` | `hiddenAt IS NULL` |
| 댓글(COMMENT) | `content`, `nickName` | `deletedAt IS NULL AND hiddenAt IS NULL` |

- 숨김·삭제된 콘텐츠는 결과·자동완성 모두에서 제외한다.
- **유저 검색**(닉네임 distinct + 작성글 수)은 백엔드에 구현돼 있으나 **프론트에 노출하지 않는다**. 프로필/유저 시스템이 없어 클릭 목적지가 없기 때문이다. 프로필 도메인 도입 시 노출한다.

## 3. 통합 검색 (결과)

검색을 실행(엔터·선택·버튼)하면 결과 카드를 표시한다.

### 3.1 매칭

- `pg_trgm` 기반 **부분 문자열(substring) 매칭** — 검색어가 필드 어디에 있든 매칭(`ILIKE %q%`)하고 유사도(similarity)로 가중한다.
- **초성 검색** — 검색어가 한글 자음(초성)만으로 이뤄지면 초성 매칭으로 전환한다. 예) `ㅈㅇ` → "자유". 쌍자음은 단자음으로 접어(folding, ㄲ→ㄱ 등) 느슨히 매칭한다.
- 통합 검색은 **부분 일치**를 유지한다(자동완성과 달리 접두로 한정하지 않음).

### 3.2 정렬

| 키 | 설명 |
|---|---|
| `relevance` | 관련순(유사도). 초성 검색 시 최신순으로 폴백 |
| `latest` | 최신순(`createdAt` DESC) |
| `comments` | 댓글많은순(`commentCount` DESC, 게시글) |

> **추천순(예정)**: 추천(vote) 기반 인기 정렬은 현재 도메인에 추천 집계 데이터가 없어(Post에 votes 컬럼 부재) **미구현**이다. 추천(vote) 도메인 도입 시 정렬 키 `popular`(추천순)를 추가한다. — TODO

### 3.3 필터

- **타입**: 전체 / 게시글 / 댓글. 각 타입의 결과 개수를 배지로 표시한다.
- **카테고리**: `PostTag`(철학·사회·정치·경제·문화·일상·기타) 또는 전체. 타입·카테고리는 독립적으로 조합한다.

### 3.4 페이지네이션

- 페이지 `size` **6**, `page` 0-base. 동률(유사도·시간 동일) 시 `createdAt`·`id`로 안정 정렬해 페이지 경계를 보장한다.
- size = 6 근거: 메인 피드(`/home`)의 `@PageableDefault(size = 6)` 설정과 동일하게 맞춰 카드 밀도를 일관되게 유지하고, 페이지당 세로 스크롤을 최소화한다.

### 3.5 결과 강조

- **댓글** 결과 스니펫은 검색어와 일치하는 부분을 색으로 강조한다(`HighlightMatch`).
- **게시글** 결과는 공용 게시글 카드를 수정 없이 그대로 재사용한다(별도 강조 없음).

## 4. 자동완성 (suggest)

입력 중 게시글 제목·닉네임에서 후보를 제안하는 드롭다운.

### 4.1 접두(prefix) 매칭

- 자동완성은 **접두 일치만** 한다(중간 위치 일치 제외). "가"를 치면 '가'로 시작하는 후보만 나오고, 중간에 '가'가 든 "국가"는 제외한다.

### 4.2 자모(jamo) 점진 매칭

- 한글을 **자모(초성+중성+종성) 단위로 완전 분해**해 접두 비교한다(`to_jamo`). 완성되지 않은 음절도 매칭한다.
- 예) "가"(ㄱ+ㅏ)는 "감정"(ㄱㅏㅁ…)·"강"·"각" 등 **ㄱㅏ로 시작하는 모든 음절**을 매칭한다. IME 입력 도중의 점진 검색을 지원한다.

### 4.3 초성 매칭

- 검색어가 자음만이면 초성 접두로 매칭한다(`to_chosung`). 예) `ㅈㅇ` → "자유·자아·정의…".

### 4.4 연관성 정렬

후보는 다음 우선순위로 정렬한다.

1. **음절 접두 일치 우선** — 입력 그대로 시작하는 후보("자"→"자유")를 자모 부분 일치("자"→"잠수")보다 위로.
2. **인기순** — 해당 제목으로 작성된 글 수 많은 순.
3. **짧은 길이** — 입력에 가까운(짧은) 후보 먼저.
4. 제목 사전순(결정적 tie-break).

### 4.5 강조 (구글식)

- 후보에서 **타이핑한 부분은 일반 굵기, 자동완성으로 덧붙는 나머지(completion)를 볼드**로 표시한다(색 없음). 예) "자유**와 나**". (`SuggestionHighlight`)
- 초성·자모 부분 일치 등 입력 문자가 후보에 그대로 들어있지 않으면 강조 없이 평문으로 표시한다.

## 5. 입력·드롭다운 UX

- **검색 실행** — 엔터·후보/최근검색 선택·🔍 버튼으로 결과를 가져온다. 타이핑만으로는 결과를 갱신하지 않는다.
- **자동완성** — 입력 200ms 디바운스로 제안하며, 최대 8개.
- **최근 검색어** — 엔터·검색 버튼·후보 선택 시에만 저장한다(타이핑 중 저장 안 함). 최대 8개, 개별·전체 삭제 가능. 입력이 비면 드롭다운에 최근 검색어를 보인다.
- **빈 결과 UX** — 결과가 없을 때 최근 검색어 칩을 다시 제시해 다음 검색 행동을 유도한다. 로딩 인디케이터로 응답 대기 상태를 표시한다.
- **키보드** — ↑/↓로 후보·최근검색 이동, Enter로 선택/검색, Esc로 닫기.
- **URL 동기화** — 검색 상태를 `?q=&type=&tag=&sort=`로 반영한다. 링크 공유·뒤로가기 시 검색 상태가 복원된다.
- **필터·정렬** — 검색 적용 후 변경 시 재검색한다(검색 후 정제).

## 6. 결과 표시·스크롤 정책

검색 결과 화면의 밀도와 스크롤 경험을 아래와 같이 설계한다. "자주 쓰고 싶은 검색"의 핵심은 결과를 보는 도중에도 검색 컨트롤이 손 닿는 곳에 있고, 각 페이지가 짧아 빠른 판단이 가능한 것이다.

### 6.1 페이지 size = 6 (메인 정합)

결과 페이지 크기는 **6**으로 고정한다(이전 10에서 변경). 메인 피드(`/home`)의 `@PageableDefault(size = 6)` 설정과 동일한 값이다.

| 효과 | 설명 |
|---|---|
| **일관된 카드 밀도** | 메인과 검색 결과가 동일한 카드 수를 보여 화면 밀도가 통일된다 |
| **세로 스크롤 최소화** | 한 페이지에 6개만 표시해 결과를 훑는 데 필요한 스크롤을 줄인다 |
| **빠른 재검색 유도** | 짧은 목록을 빠르게 소비하고 다음 페이지·다른 키워드로 전환하는 리듬을 만든다 |

### 6.2 컨트롤 헤더 sticky

검색 입력창·타입 탭·태그 필터·정렬 컨트롤로 구성된 **컨트롤 헤더 영역은 `sticky` 포지션으로 화면 상단에 고정**된다. 결과를 아무리 스크롤해도 컨트롤이 항상 따라온다.

| 효과 | 설명 |
|---|---|
| **재검색 흐름 끊김 없음** | 결과를 보다가 위로 돌아가지 않고 즉시 키워드·필터·정렬을 바꿀 수 있다 |
| **"검색 → 확인 → 재검색" 반복** | 이 사이클이 끊기지 않는 것이 자주 쓰고 싶은 검색의 핵심이다 |
| **모바일 친화** | 긴 결과 목록에서도 컨트롤이 항상 손 닿는 곳에 있다 |

## 7. 검색 엔진

- **현재**: PostgreSQL `pg_trgm`. 본 테이블을 실시간 조회하므로 색인 동기화가 불필요하다.
- **한글 함수**(애플리케이션 기동 시 생성, `IMMUTABLE`):
  - `to_chosung(text)` — 음절의 초성만 추출(쌍자음을 단자음으로 폴딩).
  - `to_jamo(text)` — 음절을 초성+중성+종성 호환 자모로 완전 분해.
- `title`·`content`·`nickName`에 GIN trgm 인덱스를, `to_chosung`·`to_jamo` 표현식에도 표현식 GIN trgm 인덱스를 둔다.
- **추상화**: `SearchEngine` 포트로 추상화되어 추후 **Elasticsearch + Nori** 교체가 가능하다. 검색 점수는 외부에 노출하지 않고 정렬 순서(`relevance`/`latest`/`comments`)만 계약으로 유지한다.

## 8. SEO·자정 퍼지

- 검색 결과 페이지(`/search`)에는 `noindex` 메타를 적용한다.
- `pg_trgm`은 실제 행을 실시간으로 읽으므로 자정 퍼지(Comment→Post 삭제) 이후 별도 색인 정리가 필요 없다. ES 전환 시에는 퍼지 배치에 색인 삭제 단계를 추가해야 한다.

## 9. 알려진 한계

본 정책은 익명·무인증 구조와 PostgreSQL 전문 검색의 한계를 전제로 한다. 아래는 의도적으로 수용한 제약이다.

- **자모 점진 접두의 과매칭** — 자모 분해 접두 특성상 "자유"가 "자율"(자유+ㄹ)에도 매칭될 수 있다. 점진 입력 편의를 위해 수용한다.
- **한 글자 초성 성능** — 1글자 초성(예 `ㄱ`)은 trgm 인덱스를 못 타 순차 스캔으로 폴백한다. 소규모 데이터 규모에서 수용한다.
- **인기 정렬은 당일 기준** — 자동완성 인기순은 동일 제목 글 수에 기반하며, 콘텐츠가 자정 초기화되므로 순위도 당일 데이터 기준이다.
- **유저 검색 미노출** — 프로필 시스템 부재로 백엔드 구현만 두고 노출하지 않는다.
- **통합 검색은 자모 점진 미적용** — 자모 점진 매칭은 자동완성에만 적용한다. 통합 결과는 부분 문자열·초성 매칭을 사용한다.

| 키 | 기본값 | 설명 |
|---|---|---|
| 결과 `size` | 6 | 통합 검색 페이지 크기(메인 피드와 동일) |

| 최근검색 보관 | 8 | 최근 검색어 최대 보관 수 |
