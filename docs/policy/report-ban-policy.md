# 신고·제재(밴) 정책

> 방구석 철학자들 — 익명 커뮤니티의 신고 누적 기반 자동 콘텐츠 숨김 및 작성 제재 정책.
> 최종 갱신: 2026-05-29

## 1. 개요

본 서비스는 로그인·회원 개념이 없는 **익명 게시판**이다. 사용자는 클라이언트에서 생성되어 `localStorage`에 영속되는 **snowflake 식별자(`userId`)** 로만 구분된다. 콘텐츠(게시글·댓글)는 **매일 자정 전체 삭제**된다.

이 환경에서 악성 콘텐츠를 통제하기 위해, 사용자 신고를 누적해 **콘텐츠 자동 숨김**과 **작성자 작성 제재(밴)** 를 적용한다. 관리자 개입 없이 임계값 도달 시 자동 동작한다.

## 2. 신고(Report)

### 2.1 신고 대상

- **게시글(POST)** 과 **댓글(COMMENT)** 모두 신고 가능.
- 신고 버튼은 프론트엔드에 실제 구현된 화면(게시글 목록 카드, 게시글 상세, 댓글)에 모달 형식으로 노출한다.

### 2.2 신고 사유 분류

| 코드 | 표기 |
|------|------|
| `SPAM` | 스팸·광고 |
| `ABUSE` | 욕설·혐오 표현 |
| `SEXUAL` | 음란·선정성 |
| `PRIVACY` | 개인정보 노출 |
| `COPYRIGHT` | 저작권 침해 |
| `ETC` | 기타 |

- 신고 시 사유 1개 필수 선택, 추가 설명(`description`)은 선택.

### 2.3 신고 기록

각 신고는 다음을 영속 저장한다.

- 신고자 식별자(`reporterId`) — 클라이언트 snowflake
- 신고자 IP(`reporterIp`) — 어뷰징 추적 및 중복 집계 방지용
- 신고 대상 작성자(`targetUserId`) — 콘텐츠가 삭제된 뒤에도 작성자별 집계가 가능하도록 신고 시점에 함께 저장
- 신고 대상 종류(`targetType`: POST/COMMENT)·대상 ID(`targetId`)
- 사유·설명·생성 시각

> 신고 데이터는 **삭제(purge)하지 않고 영속 보관**한다. 외래키를 두지 않으므로 대상 콘텐츠가 자정에 삭제되어도 신고 기록은 남으며, 향후 점수 제도의 근거가 된다.

### 2.4 신고 방지 규칙

- **자기 콘텐츠 신고 차단** — 신고자(`reporterId`)가 대상 작성자(`targetUserId`)와 같으면 거부.
- **중복 신고 차단** — 동일 신고자(`reporterId`)는 같은 콘텐츠를 1회만 신고 가능.
- **동일 IP 중복 집계 차단** — 같은 콘텐츠에 대해 동일 IP(`reporterIp`)는 1회만 임계값에 집계. 단일 단말에서 가짜 신고자 ID를 다수 생성하는 어뷰징을 완화한다.

## 3. 콘텐츠 자동 숨김

- 한 콘텐츠(게시글 또는 댓글)가 **서로 다른 신고자 `HIDE_THRESHOLD`명 이상**에게 신고되면 해당 콘텐츠를 숨김 처리한다.
- **기본값: `HIDE_THRESHOLD = 5`** (설정값으로 외부화, 무중단 변경 가능).
- 숨김 처리 시점(`hiddenAt`)을 기록·표시한다.
- 숨겨진 콘텐츠는 목록·상세 조회에서 제외(또는 숨김 안내로 치환)된다.
- 콘텐츠는 매일 자정 전체 삭제되므로 숨김 상태는 당일에만 유효하다. (의도된 동작)

## 4. 작성 제재(밴)

### 4.1 밴 조건

- 한 작성자(`targetUserId`)의 콘텐츠 중 **숨김 임계값을 넘긴(= 신고자 `HIDE_THRESHOLD`명 이상) 서로 다른 콘텐츠가 `BAN_THRESHOLD`개 이상**이면 해당 `userId`를 밴한다.
- **기본값: `BAN_THRESHOLD = 5`** (설정값으로 외부화).
- 집계는 영속 보관된 전체 신고 기록을 기준으로 한다(삭제된 콘텐츠의 신고 포함).

### 4.2 밴 효과

- 밴된 `userId`는 **게시글·댓글 작성이 차단**된다(작성 시 403).
- **조회는 제한하지 않는다** — 비로그인 조회 허용 정책과 동일하게 읽기는 자유.

### 4.3 밴 수명

- **영구 제재.** 만료·자동 해제 없음. 콘텐츠는 매일 초기화되지만 밴은 유지된다.
- 신고 기록이 영속 보관되므로 재집계 시에도 밴 상태가 일관되게 유지된다.
- 악성 사용자의 재진입을 막기 위한 강경 정책이다.

## 5. 판정 시점 (이벤트 드리븐)

- 신고 저장 시점에 즉시 [숨김 여부 → 밴 여부]를 판정한다.
- **실시간 정확성·강한 일관성은 요구하지 않는다(지연 허용).** 동시 신고로 인한 경쟁 상태는 멱등 처리로 무해하게 흡수한다.
- 집계 쿼리는 `targetUserId` 인덱스를 전제로 매 신고마다 수행한다. 부하가 문제되면 추후 캐싱·배치 집계를 도입한다.

## 6. 알려진 한계

본 정책은 익명·무인증 구조의 한계를 전제로 한다. 아래는 의도적으로 수용한 리스크다.

- **밴 우회 가능** — `localStorage`를 비우면 새 `userId`가 발급되어 제재를 회피할 수 있다. 식별자는 보안 수단이 아닌 소프트 식별자다. 매일 자정 초기화로 악성 콘텐츠 자체는 소멸하므로, 제재는 "악성 콘텐츠/사용자 통제"를 목표로 하며 완전 차단은 목표가 아니다.
- **신고 조작 여지** — `reporterId`가 클라이언트 제공 값이므로 위조 가능. IP 저장·동일 IP 중복 집계 차단으로 완화하나 완전 방지는 아니다. 향후 IP 기반 rate-limit으로 추가 강화한다.
- **신고 테이블 무한 증가** — 신고 기록을 purge하지 않으므로 행이 누적된다. 소규모 익명 게시판 규모에서 허용하며, 필요 시 보관 기간 정책을 도입한다.

## 7. 설정값 요약

| 키 | 기본값 | 설명 |
|----|--------|------|
| `report.hide-threshold` | 5 | 콘텐츠 숨김에 필요한 서로 다른 신고자 수 |
| `report.ban-threshold` | 5 | 밴에 필요한, 숨김 임계값을 넘긴 서로 다른 콘텐츠 수 |
